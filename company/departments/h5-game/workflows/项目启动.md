# H5 游戏项目启动

## 目标

让新游戏直接使用公司岗位和流程，不复制上一款游戏，也不从头重新发明制作规则。

## 启动步骤

1. 在工作区根目录创建独立项目文件夹，不在公司目录中创建游戏代码或资源。
2. 从 `../templates/项目AGENTS模板.md` 创建项目自己的 `AGENTS.md`。
3. 从 `../templates/项目开项模板.md` 创建项目开项文档，只填写需求方已知信息。
4. 创建简洁 `handoff.md`，记录当前阶段、已确认输入、风险和下一步。
5. 策划读取开项资料，主动补齐调研、未知问题、规则草案、原型范围和验收标准。
6. 按 `游戏制作流程.md` 逐阶段执行；每次切换岗位加载 `../../../roles/` 中的对应文件。

## 项目最小结构

```text
game-project/
├── AGENTS.md
├── README.md
├── handoff.md
├── docs/          # 本游戏的开项、策划和测试依据
├── src/           # 本游戏源代码
├── tests/         # 或随源码保存的本游戏测试
├── assets/        # 本游戏获得许可的功能性资源，需要时创建
└── scripts/       # 只服务本游戏的工具
```

不在项目内创建 `roles/`、`company/` 或公司工作流副本。

项目进入复盘阶段时，在工作区 `project-retrospectives/<项目名>/` 创建复盘文档，不把正式复盘保存在游戏项目中。

## 成功标准

- 新项目的项目规则能定位公司规则，但不包含岗位定义全文。
- 策划可以基于模板开工，不依赖上一款游戏的项目文件。
- 游戏专属数据不会写回公司岗位和通用标准。
